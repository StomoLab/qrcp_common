# qrcp_common — 4 実装で共有するベンチマークオプションと試験行列

`qrcp_bench.hpp` は以下の4実装が共有するヘッダオンリのライブラリ。

- `SCALAPACK_DGEQPF`  (`dgeqpf_bench`)
- `SCALAPACK_DGEQP3`  (`qrp3d`)
- `HQRRP_MPI`         (`benchmark`)
- `TileHQRRP-MPI-OpenMP` (`tilehqrrp`)

## なぜ共有するのか

試験行列の目的は**実装間の枢軸品質の比較**であり、それが意味を持つのは
4実装が**ビット単位で同一の行列**を因子化したときだけ。したがって生成器は
1箇所にしか置けない。すべての生成器は**大域添字の純関数**なので、
行列はプロセスグリッドにもブロック幅にも依存しない。

## 共通オプション

```
--res              残差 ||A*P - Q*R||_F を計算して出力に追加する（既定 off）
--matrix=<name>    試験行列を選ぶ（既定 legacy）
--dry-run          解決した設定を表示し、因子化せずに終了する
--matrix-checksum  行列を生成してチェックサムを表示し、因子化せずに終了する
--rdiag=<path>     因子化後の |R(k,k)| を全 k について CSV に追記する
--ek=<path>        打ち切り誤差 e_k (Frobenius) を全 k について CSV に追記する
```

`--matrix=NAME` と `--matrix NAME` の両方を受け付ける。
`--dry-run` は行列を確保する前に終了するので、本番サイズでも使える。

残差は4実装とも**絶対** Frobenius ノルム `‖A·P − Q·R‖_F` で、`‖A‖_F` では割らない。
そのため実装間で直接比較できるが、**問題サイズとともに増える**。無次元の値が要るときは
`‖A‖_F`（一様乱数 m×n なら約 `sqrt(mn/3)`）で割ること。

## 行列

| 名前 | 別名 | 共有 | 内容 |
|---|---|---|---|
| `legacy` | — | **✗** | 各実装が従来使ってきた生成器。既定 |
| `random` | `rand` | ✓ | 一様乱数 [-1,1)、SplitMix64 |
| `fast-decay` | `1`, `matrix1` | ✓ | 論文 Matrix 1。`A = U D V*`、`d_j = (1e-5)^((j-1)/(n-1))` |
| `s-decay` | `2`, `matrix2` | ✓ | 論文 Matrix 2。`A = U D V*`、S 字減衰 1 → 1e-6 |
| `bie` | `3`, `matrix3` | ✓ | 論文 Matrix 3。Laplace 単層ポテンシャル（正方 n のみ） |
| `kahan` | `4`, `matrix4` | ✓ | 論文 Matrix 4。`A = S K`、全列のノルムが厳密に 1 |

論文 = P.-G. Martinsson, G. Quintana-Ortí, N. Heavner, R. van de Geijn,
*Householder QR Factorization With Randomization for Column Pivoting*,
SIAM J. Sci. Comput. 39(2), C96–C115, 2017, §4.2。

### `legacy` は実装ごとに違う行列である

`legacy` は「その実装が従来使ってきた生成器」という意味で、**4実装で同じ行列ではない**。
たとえば TileHQRRP のものは列ノルムを 10^0..10^-3 に意図的に傾斜させており、
他3実装の一様乱数とは別物である。既存の計測値を再現できるよう既定にしてあるが、
**実装間の品質比較に使ってはならない**。

### 実装状況

**6種すべて実装済み。**

### `fast-decay` / `s-decay`（論文 Matrix 1, 2）の生成方式

どちらも `A = U D V^T`。`U`（m×n）と `V`（n×n）は決定的な Gauss 乱数行列の QR 分解から
作り、スペクトル `D` だけが違う（j は 0 始まり）。

**`fast-decay`（Matrix 1）** — 論文 §4.2 に明記されている。

```
d_j = (1e-5)^(j/(n-1))        d_0 = 1,  d_{n-1} = 1e-5
```

**`s-decay`（Matrix 2）** — **論文に式が無い。** 本文は「まず 1 付近に留まり、急減衰し、
1e-6 で平坦になる」という記述だけで、あとは Fig.7 / Fig.10 のグラフのみ。以下は
**Fig.10 (n=4000) からの読み取り**で、そのことを論文化の際に明記すること。

```
d_j = 10^(-6 * S(x)),  x = (j/(n-1) - 0.3125) / 0.04,  S(x) = 1/(1+exp(-x))
```

- `centre = 0.3125` … `d_j = 1e-3` になる位置。Fig.10 の黒線が 1e-3 を切るのが
  k ≈ 1250 / 4000 = 0.31 なのに合わせた
- `width = 0.04` … ロジスティックの 10%〜90% 遷移幅は `2*ln(9)*width = 0.176*(n-1)`
  ≈ 700 列。Fig.10 の降下が k ≈ 1000〜1700 に広がるのに合わせた

n=4000 での値: `d_0 = 0.994`、`d_500 = 0.881`、`d_1000 = 0.091`、`d_1250 = 9.9e-4`、
`d_1700 = 2.2e-6`、`d_3999 = 1.0e-6`。

**要素ごとの純関数として書けない**ので、他の行列と違って **rank 0 で構成して全ランクに
複製する**（`qrcp::build_global`）。そのため次の制約がある。

- `m*n <= 8192²` を超えるとエラー。全ランクに複製するため（4000×4000 で 128 MB）。
  論文の品質実験は 4000×4000 なので実用上の制約にはならないが、**速度ベンチの
  N=10240/20480 には使えない**。
- 生成に LAPACK の `dgeqrf`/`dorgqr` と BLAS の `dgemm` を使うので、**行列が
  BLAS/LAPACK 実装に依存する**。同一ジョブ内の4実装は同じライブラリを使うので
  一致するが、ローカル (OpenBLAS) と HUCC (MKL) では別の行列になる。
  比較の前に `--matrix-checksum` で一致を確認すること。
- 検証: `U`, `V` が直交なので `‖A‖_F = ‖D‖_F` が機械精度で成立する（実測 rel diff ~1e-15）。
  また `max_j ‖A(:,j)‖ = |R(0,0)|`（最初の枢軸は最大列ノルムを選ぶ）も一致する。

### `kahan`（論文 Matrix 4）

論文 §4.2 と p.C110 に完全に指定されている。閉形式なので**要素ごとの純関数**であり、
複製が不要（`fast-decay` / `s-decay` と違ってサイズ制限がない）。

```
A = S K,  S = diag(1, ζ, ζ², …),  K は単位上三角で非対角が −φ,  ζ² + φ² = 1

A(i,j) = 0        (j < i)
       = ζ^i      (j = i)
       = −φ·ζ^i   (j > i)

ζ = 0.99999,  φ = sqrt(1−ζ²) = 4.472124774635e-03
```

`ζ^i` は `std::pow` ではなく2進累乗で計算する。`pow` は libm 実装ごとにビット単位で
違いうるが、4実装で同じ行列である必要があるため。

**定義の要点**: 全列のノルムが厳密に 1 になる。

```
‖A(:,j)‖² = φ²(1−ζ^{2j})/(1−ζ²) + ζ^{2j} = 1
```

実測で `max_j | ‖A(:,j)‖ − 1 |` は n=64 で 1.1e-16、n=20480 で 2.0e-14。
したがって古典的な列ピボットは毎ステップ完全な同点を見ることになり、これが反例の趣旨。

**論文の図との差（実害なし）**: 論文 Fig.10 の Matrix 4 は `|R(k,k)|` が 0.087〜0.095 に
収まっているが、上の定義そのままだと `|R(0,0)| = 1`（最大列ノルム）になる。Fig.9 の
作用素ノルムで `e_0 ≈ 1` であることから、論文は Kahan 行列を `‖A‖₂ = 1` に正規化して
いると思われる。**QRCP は定数倍に不変なので枢軸列も相対的な品質も一切変わらず、
グラフの y 軸が動くだけ**。ここでは §4.2 の記述どおり正規化せずに実装した。

**有限精度での挙動**: 列ノルムは厳密には等しいが浮動小数点では最終 ulp が違うため、
LAPACK `dgeqp3` は実際には**大量に列を入れ替える**（n=1024 で 1024/1024 の位置が
恒等でない）。それでも `|R(k,k)|` はほぼ 1 のまま推移し、小さい特異値を顕在化できない。
これが Kahan 反例の本質。

### `bie`（論文 Matrix 3）

平面上の滑らかな閉曲線上の Laplace 単層作用素

```
(S φ)(x) = −1/(2π) ∫_Γ log|x − y| φ(y) ds(y)
```

の Nyström 離散化。対数特異性は Kress（Martensen–Kussmaul）分解

```
log|x(t)−x(τ)| = ½ log(4 sin²((t−τ)/2)) + ½ log( |x(t)−x(τ)|² / (4 sin²((t−τ)/2)) )
```

で扱う。第2項は解析的（τ→t で `log|x'(t)|²` に収束）。第1項は厳密重み

```
R_d = −(2π/M) Σ_{k=1}^{M−1} cos(kπd/M)/k − (π/M²)(−1)^d,   M = n/2
```

で積分し、第2項は台形則。Kress, *Linear Integral Equations*, §12.3。

**論文からの逸脱（重要）**: 論文 §4.2 は **Alpert の6次ハイブリッド Gauss-台形則**を指定して
いる。ここでは Kress の求積を使った。理由は、Alpert の補助節点・重み表 [Alpert, SISC 20
(1999)] を手元の資料なしに正確に再現できず、**記憶で重みを書けばもっともらしいが誤った
行列ができる**ため。Kress 則はこの作用素に対するもう一つの標準的選択で、6次ではなく
スペクトル精度であり、表が要らない。**作用素・曲線の性質・悪条件性**（枢軸品質の実験が
見ている当のもの）は同じ。Alpert の表が入手できれば差し替えは容易。

**曲線も論文では未指定**。ここでは滑らかな星形 `r(t) = 1 + 0.3 cos(3t)`、
`x(t) = (r cos t, r sin t)` を使う。

**制約**: 正方の Nyström 系なので **`m == n` かつ `n` が偶数**であることを要求する
（違反すると明示的にエラー）。`fast-decay` / `s-decay` と同じく複製するので
`m*n <= 8192²`。

**検証**: 核 `−1/(2π) log|x−y|` は対称なので、行列は `A_ij / speed_j = A_ji / speed_i`
を満たさねばならない。実測の相対誤差は n=64 で 9.1e-16、n=1024 で 1.0e-14。
特異値は `1/k` で減衰し（2次元 Laplace 単層作用素は −1 次の擬微分作用素なので正しい）、
条件数は n にほぼ比例する（n=1024 で 7.98e2）。

## 品質の指標: |R(k,k)| と e_k

論文の品質実験は2つの量を見る。どちらも CSV に追記する tidy 形式（メタデータを毎行
繰り返す）なので、複数の実行結果を1つのファイルに連結できる。

| オプション | 量 | 論文 |
|---|---|---|
| `--rdiag=<path>` | `\|R(k,k)\|` | Fig.10 |
| `--ek=<path>` | `e_k`（Frobenius ノルム） | Fig.6〜9 の右パネル、式 (4.2) |

### e_k の計算

```
e_k = ‖ A·P − Q(:,1:k)·R(1:k,:) ‖ = ‖ R((k+1):n, (k+1):n) ‖
```

**推定ではなく厳密に**計算する。`R` は上三角なので k の右下ブロックは k+1 のそれに
第 k 行を足したものであり、

```
e_n = 0,    e_k² = e_{k+1}² + Σ_{j≥k} R(k,j)²
```

が成り立つ。したがって `R` の各行の二乗和（長さ n の縮約1回）から全 n+1 個が出る。

参照線は Eckart–Young 下界 `e_k ≥ (Σ_{j>k} σ_j²)^{1/2}` で、スペクトルを指定した行列
（`fast-decay`, `s-decay`）でのみ厳密に書ける。

**作用素ノルムは未実装**。論文 Fig.6〜9 の左パネルは `‖R((k+1):n,(k+1):n)‖₂` で、
これは k ごとに右下ブロックの最大特異値が要る（SVD かべき乗法を n 回）。Frobenius 版が
`O(局所要素数)` で済むのに対し `O(n³)` 以上かかるので、別の作業項目とした。

**検証**（4実装・4行列すべてで成立）:

- `e_0 = ‖A‖_F`（`Q` は直交・`P` は置換なので厳密に等しい）。`fast-decay` n=512 で
  4実装とも `4.764053203645e+00` = `‖D‖_F` と**13桁完全一致**
- `e_n = 0` が厳密に成立
- Eckart–Young 下界の違反 **0 / 513**

## |R(k,k)| の出力とプロット

`--rdiag=<path>` は因子化後の `|R(k,k)|` を全 k について CSV に**追記**する。
これは論文 Fig.10 の量で、列ピボット QR では単調減少して特異値を追いかける。
その追従の良さが枢軸品質の指標になる。

CSV は tidy 形式（メタデータを毎行繰り返す）なので、複数の実行結果を1つのファイルに
連結できる。

```
implementation,matrix,m,n,mb,nb,P,Q,k,abs_rkk,sigma
SCALAPACK_DGEQP3,fast-decay,512,512,64,64,1,2,0,2.820703633478e-01,1.000000000000e+00
```

`sigma` 列（`--ek` では `eckart_young` 列）はスペクトルが既知の行列
（`fast-decay`, `s-decay`）でのみ埋まり、プロットの黒い参照線になる。

`plot_quality.py` は列の並びから2つの量を判別するので、同じコマンドでどちらも描ける
（混ぜて渡すとエラーになる）。

```sh
# 4実装を同じ CSV に追記する
for impl in ...; do ... --matrix=fast-decay --rdiag=rdiag.csv; done

# 論文 Fig.10 相当のグラフ (gnuplot が要る。matplotlib は不要)
python3 qrcp_common/plot_quality.py -o rdiag.png rdiag.csv
python3 qrcp_common/plot_quality.py -o rdiag.pdf --matrix fast-decay rdiag.csv

# e_k も同じスクリプトで
python3 qrcp_common/plot_quality.py -o ek.png ek.csv
```

| SCALAPACK_DGEQPF | **0** / 511 | **0** / 1023 | **0** / 1023 | **0** / 1023 |

ただし論文でその差が大きく出るのは**作用素ノルム**（Fig.9 左）であり、Frobenius

### ビルド設定を揃えること

行列を実行時に組み立てる種別（`fast-decay` / `s-decay` / `bie`）は、**4実装を同じコンパイラ・
同じ最適化設定でビルドしないと同じ行列にならない**。実際、`bie` の開発中に片方を最適化なし・
片方を Release でビルドしたところチェックサムが割れた（融合積和の有無で丸めが変わるため）。
`bie` の組み立てでは `#pragma clang fp contract(off)` で融合積和を止めてあるが、
**比較の前に `--matrix-checksum` で一致を確認する運用が必要**。

論文は「古典的列ピボットでは対角が厳密に単調減少するが、ランダム化戦略ではこの性質は
保証されない」と述べており、実測はそのとおりになっている。TileHQRRP の違反が桁違いに
多いのは、ランダム化に加えて**「制限付き正味置換」**を使っているため（`hqrrp.cpp` 冒頭の
設計コメント参照）。

## データ確保の統一

4実装は A の分散方法が同じ（ブロック `(mb, nb)` の2次元ブロックサイクリック、
`nprow × npcol` グリッド、source (0,0)）で、**局所データの持ち方だけが違う**。

| 実装 | 局所格納 | 入口 |
|---|---|---|
| DGEQPF / DGEQP3 / HQRRP_MPI | 局所配列1本、列優先、単一の leading dimension | `qrcp::fill_local` |
| TileHQRRP-MPI-OpenMP | ts×ts タイルを個別に格納、タイルごとの ld | `qrcp::fill_tile` |

両方の入口が同じ `qrcp::Entries`（要素の供給元）を通るので、**4実装は同じ種別に対して
ビット単位で同一の行列を生成する**。端タイルの余白の 0 埋めも `fill_tile` が行う。

`legacy` も同じ経路を通る（`Entries::legacy` に各実装の従来の生成器を渡す）ので、
生成コードは実装ごとに1本ずつしかない。

### 検証

`--matrix-checksum` は行列の全大域要素を1回ずつ XOR で畳み込んだ値を出す。
XOR なのでプロセスの寄与順に依存せず、大域添字も混ぜてあるので値が誤った位置に
入れば検出できる。**4実装・任意のグリッド・任意のブロック幅で同じ値が出なければならない。**

```
$ mpirun -np 2 ./dgeqpf_bench 512 512 64 1 2 --matrix=random --matrix-checksum
matrix-checksum 15af78842aaef285  SCALAPACK_DGEQPF         m=512 n=512 block=64x64 grid=1x2
$ mpirun -np 2 ./qrp3d           512 512 64 1 2 --matrix=random --matrix-checksum
matrix-checksum 15af78842aaef285  SCALAPACK_DGEQP3         m=512 n=512 block=64x64 grid=1x2
$ mpirun -np 2 ./benchmark -M 512 -N 512 -b 64 -P 1 -Q 2 --matrix=random --matrix-checksum
matrix-checksum 15af78842aaef285  HQRRP_MPI                m=512 n=512 block=64x64 grid=1x2
$ mpirun -np 2 ./tilehqrrp       512 512 64 32 10 1 2 --matrix=random --matrix-checksum
matrix-checksum 15af78842aaef285  TileHQRRP-MPI-OpenMP     m=512 n=512 block=64x64 grid=1x2
```

## ビルドへの組み込み

各プロジェクトの CMake で include パスに追加するだけ。

```cmake
target_include_directories(<target> PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/../qrcp_common)
```

4実装とも `CMAKE_CXX_STANDARD 17`。共有ヘッダを別々の標準でコンパイルするのは
潜在的な危険なので揃えてある（SCALAPACK_DGEQPF は C++11 だったのを 17 に上げた）。
